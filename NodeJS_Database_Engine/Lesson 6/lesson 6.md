# Лекция 6: Синтаксический анализатор (SQL Parser) и движок выполнения запросов на Node.js

> **Цель лекции:** Научить нашу базу данных понимать человеческий язык SQL. Мы разберем теорию компиляторов: напишем лексический анализатор (*Lexer*), синтаксический анализатор методом рекурсивного спуска (*Parser*), построим абстрактное синтаксическое дерево (*AST*) и реализуем движок исполнения (*Execution Engine*) с оптимизацией поиска по первичному ключу.

---

## 1. Как компьютер понимает SQL: Три фазы обработки запроса

Когда мы пишем запрос:
```sql
SELECT id, name FROM users WHERE age >= 18 ORDER BY id DESC LIMIT 5;
```
Для компьютера это просто бессмысленный массив символов: байты `'S'`, `'E'`, `'L'`, `'E'`, `'C'`, `'T'`... Чтобы превратить эту текстовую строку в осмысленные действия на диске, процессор запросов СУБД выполняет три последовательные фазы:

```
    Сырая строка SQL: "SELECT id, name FROM users WHERE age >= 18..."
                                │
                                ▼
  ┌───────────────────────────────────────────────────────────────┐
  │ 1. ЛЕКСИЧЕСКИЙ АНАЛИЗ (Lexer / Tokenizer)                     │
  │    Разбиение строки на типизированные неделимые токены         │
  └─────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼  Поток токенов: [KEYWORD, IDENT, COMMA...]
  ┌───────────────────────────────────────────────────────────────┐
  │ 2. СИНТАКСИЧЕСКИЙ АНАЛИЗ (Parser — Рекурсивный спуск)         │
  │    Проверка грамматики и построение древовидного AST          │
  └─────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼  Объект AST (Abstract Syntax Tree)
  ┌───────────────────────────────────────────────────────────────┐
  │ 3. ДВИЖОК ВЫПОЛНЕНИЯ (Execution Engine)                       │
  │    Оптимизация, обращение к StorageEngine и проекция колонок  │
  └─────────────────────────────┬─────────────────────────────────┘
                                │
                                ▼
                       Результат: массив строк
```

## 2. Фаза 1: Лексический анализатор (Lexer / Tokenizer)

Задача лексера — отсечь пробелы и сгруппировать символы в неделимые смысловые единицы — **токены (Tokens)**.

Каждый токен характеризуется:
* `type` — тип токена (`KEYWORD`, `IDENTIFIER`, `NUMBER`, `STRING`, `OPERATOR`, `COMMA`, `SEMICOLON`).
* `value` — сырое значение (например, `'SELECT'`, `'users'`, `18`, `'>='`).
* `position` — номер символа в исходной строке (для вывода понятных сообщений об ошибках).

### Как устроен лексер в `lexer.js`:

Лексер бежит по строке указателем `pos`:
1. Если встречает кавычку (`'` или `"`) — собирает все символы до закрывающей кавычки в токен `STRING`.
2. Если встречает цифру — считывает число в токен `NUMBER`.
3. Если встречает буквы — считывает слово целиком. Затем проверяет по справочнику ключевых слов (`KEYWORDS`): если слово входит в список (`SELECT`, `INSERT`, `WHERE`...), то это `KEYWORD`, иначе — имя таблицы или колонки (`IDENTIFIER`).
4. Если встречает знаки `<`, `>`, `=`, `!` — аккуратно проверяет следующий символ (чтобы распознать двухсимвольные операторы `>=`, `<=`, `!=`).

Пример результата работы лексера:
```
Вход:  SELECT name FROM users WHERE age = 20;
Выход: [KEYWORD: 'SELECT', IDENTIFIER: 'name', KEYWORD: 'FROM', 
        IDENTIFIER: 'users', KEYWORD: 'WHERE', IDENTIFIER: 'age', 
        OPERATOR: '=', NUMBER: 20, SEMICOLON: ';']
```

## 3. Фаза 2: Синтаксический анализатор (Parser) и AST

После того как токены получены, в дело вступает **Парсер**. Он проверяет, соответствуют ли токены правилам грамматики SQL.

Мы применили классический метод **рекурсивного спуска (Recursive Descent Parsing)**:
* Каждая грамматическая конструкция языка описывается отдельным методом: `parseCreateTable()`, `parseInsert()`, `parseSelect()`, `parseUpdate()`, `parseDelete()`.
* Парсер заглядывает вперед (`current()`, `peekNext()`), сверяет ожидаемый тип токена (`expectKeyword`, `expectType`) и продвигает указатель.

### Что такое AST (Abstract Syntax Tree)?

AST — это дерево синтаксического разбора запроса, представленное в виде иерархического объекта JavaScript.

Для запроса:
```sql
SELECT id, name FROM users WHERE age >= 18 ORDER BY id DESC LIMIT 5;
```

Наш парсер строит следующий понятный объект AST:

```json
{
  "type": "SELECT",
  "table": "users",
  "columns": ["id", "name"],
  "where": [
    {
      "field": "age",
      "op": ">=",
      "value": 18
    }
  ],
  "orderBy": {
    "field": "id",
    "direction": "DESC"
  },
  "limit": 5
}
```

С таким объектом компьютеру работать неизмеримо проще, чем с сырым текстом: все параметры разложены по полочкам!

## 4. Фаза 3: Движок выполнения (Execution Engine)

Файл `executor.js` берет дерево AST и превращает его в вызовы нашего дискового движка хранения `StorageEngine`:

### 1. Поддержка нескольких таблиц и схемы (`_schemas.json`)
Каждая таблица в нашей базе данных имеет:
* Свой файл данных (`users.db`, `orders.db`).
* Свой журнал опережающей записи (`users.wal`).
* Описание списка колонок (схему), сохраняемую в JSON-файле метаданных.

### 2. Оптимизация запроса: Index Lookup за $O(1)$ против Full Table Scan
Посмотрите на эту строчку в `executor.js`:

```javascript
// Проверяем: нет ли в условии WHERE точного равенства по первичному ключу id?
const idCondition = ast.where?.find(cond => cond.field.toLowerCase() === 'id' && cond.op === '=');

if (idCondition) {
  // БИНГО! Используем хэш-индекс в памяти и читаем ровно 1 запись с диска!
  const record = await storage.get(Number(idCondition.value));
  if (record && this.evaluateConditions(record, ast.where)) {
    rows.push(record);
  }
} else {
  // Иначе запускаем полное сканирование с предикатом
  rows = await storage.scan(record => this.evaluateConditions(record, ast.where));
}
```
Это простейший, но настоящий **Оптимизатор запросов (Query Optimizer)**! Если студент делает выборку по первичному ключу (`WHERE id = 42`), наш движок не тратит ресурсы на сканирование гигабайтного файла, а мгновенно берет смещение из Keydir и отдает результат.

### 3. Сортировка (`ORDER BY`), ограничение (`LIMIT`) и проекция
После выборки строк движок:
1. Сортирует массив через компаратор по выбранному полю (`ASC` / `DESC`).
2. Отрезает лишние строки с помощью `.slice(0, limit)`.
3. Оставляет только запрошенные пользователем колонки (`SELECT id, name` отбрасывает лишние поля объекта).
